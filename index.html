Cada respuesta de una API
lleva su propia guía de envío.

Así como una encomienda física necesita un estado claro para que remitente y destinatario sepan qué está pasando con ella, cada petición HTTP recibe un código de estado que indica si el paquete de datos llegó bien, se redirigió, se perdió en el camino o nunca salió de la bodega. Esta sección presenta el proyecto y sirve de punto de partida para explorar los códigos de estado HTTP.

Introducción

¿Qué son los códigos de estado HTTP y por qué importan?

Un código de estado HTTP es un número de tres cifras que el servidor devuelve en cada respuesta para decirle al cliente qué pasó con su solicitud. En un sistema como el backend de EncomiExpress, donde el frontend consulta constantemente rutas, ventas, conductores o anticipos, ese código es la forma en que la API "etiqueta" cada respuesta: si fue exitosa, si falta autenticación, si el dato no existe o si algo falló en el servidor.

01

Comunican sin ambigüedad

Reemplazan mensajes de error genéricos por un estándar que cualquier desarrollador, en cualquier lenguaje, puede interpretar igual.

02

Guían el manejo de errores

El frontend decide qué mostrar al usuario —una alerta, un redireccionamiento al login, un reintento— según el código recibido.

03

Facilitan la depuración

Al probar endpoints o revisar logs, el código de estado es la primera pista para saber si el problema está en el cliente o en el servidor.

Categorías

Las cinco etapas de una respuesta

Los códigos se agrupan en cinco familias según su primer dígito. Puede pensarse como el recorrido de una encomienda: información en tránsito, entrega exitosa, redirección de ruta, problema del remitente o falla del transportista.

1xx→ 2xx→ 3xx→ 4xx→ 5xx
1xx

Informativos

El servidor confirma que recibió la solicitud y sigue procesándola. Son respuestas provisionales.

en tránsito
2xx

Éxito

La solicitud se recibió, entendió y procesó correctamente. Es la entrega sin novedad.

entregado
3xx

Redirección

Se necesita una acción adicional, normalmente ir a otra URL, para completar la solicitud.

ruta desviada
4xx

Error del cliente

La solicitud tiene un problema atribuible a quien la envió: datos mal formados, sin permisos o inexistentes.

remitente
5xx

Error del servidor

El servidor falló al intentar cumplir una solicitud aparentemente válida. La falla es del transportista.

transportista

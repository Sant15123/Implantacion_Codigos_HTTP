Códigos HTTP asignados al equipo

Esta página documenta los códigos de estado HTTP asignados al equipo de desarrollo, con su nombre oficial, descripción y un ejemplo práctico aplicado al backend de EncomiExpress. Sirve como referencia rápida para interpretar respuestas en el flujo real de la API.

Códigos asignados

Código HTTP, nombre oficial y contexto de uso dentro del sistema EncomiExpress.

Código HTTP Nombre Oficial Descripción / Contexto de uso
200 OK La solicitud se procesó con éxito. Ejemplo: al consultar el estado de una encomienda ya registrada.
201 Created Se creó un nuevo recurso. Ejemplo: al registrar una nueva encomienda en el sistema.
202 Accepted La solicitud fue aceptada pero aún se está procesando. Ejemplo: al programar una recolección que se confirmará más tarde.
204 No Content La operación fue exitosa pero no hay contenido que devolver. Ejemplo: al eliminar el registro de un conductor.
400 Bad Request La solicitud tiene datos o sintaxis inválida. Ejemplo: enviar un formulario de encomienda sin el campo de destinatario.
401 Unauthorized Falta autenticación válida. Ejemplo: intentar consultar rutas sin un token de sesión.
403 Forbidden El cliente está identificado pero no tiene permisos. Ejemplo: un conductor intentando acceder al panel de administración.
404 Not Found El recurso solicitado no existe. Ejemplo: consultar una encomienda con un ID inexistente.
405 Method Not Allowed El método HTTP no está permitido en ese endpoint. Ejemplo: usar DELETE en una ruta que solo acepta GET.
409 Conflict La solicitud entra en conflicto con el estado actual del recurso. Ejemplo: intentar registrar dos veces la misma guía.
415 Unsupported Media Type El formato del cuerpo de la solicitud no es soportado. Ejemplo: enviar XML cuando la API solo acepta JSON.
422 Unprocessable Entity Datos sintácticamente correctos pero que violan reglas de negocio. Ejemplo: una fecha de entrega anterior a la fecha de recolección.
429 Too Many Requests Se superó el límite de solicitudes permitidas. Ejemplo: consultar el estado de rutas demasiadas veces en poco tiempo.
500 Internal Server Error Ocurrió un error inesperado en el servidor. Ejemplo: una falla no controlada al calcular una tarifa de envío.
501 Not Implemented El servidor no soporta la funcionalidad solicitada. Ejemplo: una futura ruta de tracking en tiempo real aún no implementada.
502 Bad Gateway Un servidor intermedio recibió una respuesta inválida de otro servidor. Ejemplo: fallo de comunicación entre el gateway y el microservicio de pagos.
503 Service Unavailable El servidor no está listo para atender solicitudes (mantenimiento o sobrecarga). Ejemplo: durante un despliegue del backend.
504 Gateway Timeout Un servidor intermedio no recibió respuesta a tiempo de otro servidor. Ejemplo: consulta a un proveedor externo de geolocalización que tarda demasiado en responder.
